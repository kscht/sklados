| D-46 | Одна раскладка на kind при несущем subtype (`event/appointment`, `device/role`) | `ui_subtypes: {<subtype>: {…}}` на том же концепте, **merge поверх** базового `ui`; отдельных концептов не плодим | ✅ решён (2026-07-21) |
| D-47 | Пикеры форм (кому назначить / кому одолжить / куда положить) | один generic `EdgeTargetPicker(predicate)`: читает `to_kinds` концепта ребра, разворачивает классы (D-43/D-51) — специализированные пикеры не хардкодятся | ✅ решён (2026-07-21) |
| D-48 | Контракт action-виджетов (закрывает D-16) | v1, три сорта: `mutate` (sets, валидация статуса под-схемой), `relate` (диалог из типизации ребра), `job` (создаёт job по template; задел под плейбуки) | ✅ решён (2026-07-21) |
| D-49 | Клик-экономия генерируемого UI («Salesforce-итис») | правила движка: `form_quick` (1–2 поля) + progressive disclosure; **контекст экрана = дефолты формы**; пустой виджет не рендерится (кроме `always`), `ui.header` ≤ 5; search-first (`/`); bulk и inline-edit — свойство NodeList; action `clone`. Клик-бюджеты — DoD фаз (добавить ≤3, найти ≤2, переложить =1, одолжить ≤3, bulk-категоризация ≤4) | ✅ решён (2026-07-21) |
| D-50 | Вертикаль «Склад»: захардкоженный раздел или данные | **workspace-as-data**: `kind='view', subtype='workspace'`, один маршрут `/w/[slug]`; список вертикалей = запрос view-узлов с `can_access`; в коде только шелл (логин, рендерер, реестр компонентов, generic-фолбэк при пустой базе); системные view — в seed. Workspace — линза; хранилища — `location`, перенос вещей — пересадка `contains` | ✅ решён (2026-07-21) |
| D-51 | Холодильник/шкаф/сейф — и вещь, и место хранения | «складскость» — роль, не тип: мета-класс `container` = {location, item, device}; `contains.from_kinds = ['container']`; дерево хранения = **обход рёбер**, не фильтр `kind='location'`; критерий: важна вещность (бренд/гарантия/поломка/продажа) → `item`-контейнер, чистое адресуемое пространство → `location`; пограничные (полка) — оба легальны | ✅ решён (2026-07-21) |
| D-52 | Комплектующие в device: `contains` или `part_of` | `contains` = физическое местонахождение **всегда**, включая «установлено» (флаг `installed: true` на ребре); `part_of` = несъёмная структура (багажник у Весты). Единая история перемещений: полка → NUC → полка; ремонт = `task` + `needs`/`used` со склада запчастей | ✅ решён (2026-07-21) |
| D-53 | Главная парадигма навигации: сайдбар+таблицы или пространственный «рабочий стол» (iOS-springboard из иконок-узлов) | **desktop — главный вход приложения**: `/` открывает грид иконок (узлы, папки, workspace'ы); раскладка — упорядоченная сетка в стиле iOS (поле `order`, без свободных координат); папка = `view(subtype='desktop')`, вложенность любая, перетащил иконку на иконку → папка; иконки — из `ui.graph` концепта kind + пер-узловое поле `icon`. Таблицы/карточки/дерево остаются рабочими экранами внутри | ✅ решён (2026-08-02) |
| D-54 | Механика размещения и «симлинки»: узел в нескольких местах (закладки, папки проектов) | размещение = ребро **`references`** (`desktop →references→ узел SET order`) — навигационная связь, канон 27 не расширяется; `part_of` не использовать (ложно-структурно). «Симлинк» = ещё одно `references`-ребро на тот же узел: узел один, размещений много, удаление размещения не трогает узел; папки шарятся через `can_access`, личные закладки = персональный desktop (D-19) | ✅ решён (2026-08-02) |
| D-55 | UX стола по фидбеку: защита от случайных перемещений, ручная сортировка, пустые места, мультивыделение | **пересматривает часть D-53** («поток iOS» → «слоты»): (1) режим просмотра — dnd выключен полностью, только явный режим «Изменить»; (2) разреженная сетка: поле `slot` на ребре размещения, `grid_cols` на столе, пустые ячейки легитимны, **авто-уплотнения нет** — сортировка только ручная; (3) мультивыделение: клик = toggle, shift = диапазон; групповые перенос/папка/симлинк/убрать | ✅ решён (2026-08-06) |
| D-56 | Стек UI: Next.js «тяжёлый» — оставаться или мигрировать | **Vite + React SPA** (React и виджеты сохранены — D-14 в силе): приватному инструменту SSR/SEO не нужны, а LIVE SELECT и офлайн-PWA хотят клиентский data-слой; прод = статика за nginx + same-origin `/db`-прокси к SurrealDB (Authorization инжектится в nginx, браузер кредов не видит); TanStack Query; после этапа F браузер пойдёт в SurrealDB напрямую с Keycloak-JWT и прокси упростится. До Keycloak весь сайт закрыт basic auth (`WEB_BASIC_*` в .env). Миграция выполнена в день решения (~700 строк) | ✅ решён, выполнено (2026-08-06) |
