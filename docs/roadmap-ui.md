# Роадмап разработки UI

Сведённый актуальный план интерфейса — поверх [`roadmap-inventory.md`](roadmap-inventory.md) (фазы 3–10) с учётом всех поправок: ревизии UI (D-44…D-50 в [`ui-architecture.md`](ui-architecture.md)), контейнеров (D-51/D-52) и пересмотра D-33 (категории уже проставлены — inbox-first отменён, фильтры по иерархии доступны сразу).

## Где мы сейчас (фаза 2 v1 — сделано, 2026-08-02)

✅ Работает на https://v1.spiridus.ru:
- `/w/[slug]` — универсальный рендерер workspace-узлов: сайдбар и home читаются из графа (D-50);
- v1-рендереры: `smart_list` (generic-таблица), `tree` (иерархия локаций);
- `/things` — generic-фолбэк (ступень 5 лестницы D-44);
- 44 категории с иерархией и статусы с `_i18n`+цветом уже в данных.

❌ Ещё нет: карточек узлов, виджетов, форм, фильтров, действий, прав, i18n-переключателя.

## Сквозные правила движка (действуют с этапа A, из D-45/D-49)

1. Пустой виджет не рендерится (кроме `always`); `ui.header` ≤ 5 виджетов.
2. Контракт виджета = план запроса: раскладка собирается в **один** SELECT (анти-N+1).
3. Виджет без реализации в реестре → generic-фолбэк с бейджем, не падение.
4. Контекст экрана = дефолты формы создания.
5. Клик-бюджеты — часть DoD этапов (см. таблицы ниже), не пожелание.

## Этап A — Виджетный фундамент + `<NodeCard>` (≈ 3–4 дня)

**Цель:** клик по любой строке открывает карточку узла, собранную из каталога.

| Артефакт | Детали |
|---|---|
| Реестр виджетов | slug → React-компонент; контракты машинно (D-45) |
| `<Widget>`-диспетчер + `<NodeCard>` | читает `ui` с концепта kind, лестница D-44 (ступени 3→5) |
| Стартовые виджеты (~12) | `Title`, `Description`, `Timestamps`, `WikidataLink`, `CategoryChip`, `BrandChip`, `StatusChip` (цвет из словаря), `QuantityDisplay`, `LocationCrumb` (←contains), `ContainedItems` (→contains, с бейджем `installed`), `LentToCard`, `RepresentsDocs` |
| Декларация `ui` на `kind_item` (+ `kind_location`, `kind_device`) в seed | `ui_subtypes` merge (D-46) |
| Маршрут `/n/[id]` + кликабельные строки таблиц | |

**DoD:** карточка перфоратора — категория-чип, крошки «Гараж → Верстак», пусто схлопнуто; карточка холодильника Bosch — содержимое (молоко, пельмени) и гарантийный талон; карточка NUC — SSD/RAM с бейджем «установлено». Все три — **без единого kind-специфичного компонента**.

## Этап B — `<NodeList>`: фильтры, поиск, bulk (≈ 2–3 дня)

**Цель:** списки становятся рабочим инструментом поиска.

| Артефакт | Детали |
|---|---|
| `<NodeList>` по `ui.list_columns` | колонки-виджеты, сортировка, пагинация |
| Фильтр по категории **с обходом иерархии** | выбрал «агрохимия» → попали и удобрения, и Эпин (данные уже готовы) |
| Фильтр по локации рекурсивно | «гараж» → включая шкафы и холодильник в нём |
| Search-first | хоткей `/`, поиск по `name`, Enter → топ-результат |
| Bulk-выделение + inline-edit статуса/категории в ячейке | свойство NodeList, D-49 |

**DoD (клик-бюджеты):** найти вещь ≤ 2 действий; смена статуса из списка ≤ 2; bulk-категоризация 25 вещей ≤ 4.

**Цель:** вещи заводятся из UI, быстро.

| Артефакт | Детали |

| Action `clone` («ещё такой же») | |
| Маршруты `/n/new`, `/n/[id]/edit`; «+» в дереве и списках | контекст = дефолты |

**DoD:** добавить вещь в текущую полку ≤ 3 действий («+» → имя → Enter, `contains` проставлен сам); создание категории «телефон» — один диалог, три операции одной транзакцией.

## Этап E — i18n-переключатель (≈ 1 день)

Все метки (kind, категории, статусы, виджеты) — из `_i18n` концептов; они **уже в данных** с фазы 1. Ru/en-переключатель в шапке; контент (`name`) остаётся на языке оригинала. **DoD:** «Холодильники» ↔ «Refrigerators», имя вещи не переводится.

## Этап F — Права и вход через Keycloak (≈ 2–3 дня, фаза 8 роадмапа, D-11)

Своего логина **нет** — вход через Keycloak (OIDC): Auth.js с Keycloak-провайдером в web; `DEFINE ACCESS TYPE JWT` (JWKS realm'а) + `AUTHENTICATE`-маппинг claim → узел `person` (JIT-провижининг при первом входе); обобщённый `PERMISSIONS WHERE` по [`access-control.md`](access-control.md) — без изменений; `<AccessGrantsWidget>` + модалка «поделиться»; root-доступ web выключается. **DoD:** редирект на Keycloak → сессия; сын видит только игрушки; папа поделился полкой — мама сразу её видит.

## Этап G — Actions v1 + lent-workflow (≈ 1–2 дня, фаза 9)

Контракт D-48: `mutate` (`mark_done`) и `relate` (`lend` → диалог `party`-пикера, `return`). View «Одолжено» уже существует. **DoD:** одолжить ≤ 3 действий; вернуть = 1. (`job`-действия — с воркерами, вне UI-роадмапа.)

## Этап H — PWA + мобильный (≈ 2–3 дня, фаза 10)

Automatic responsive (D-18), манифест + SW (офлайн-просмотр), камера для фото, опц. сканер штрих-кода → Wikidata-автозаполнение. **DoD:** добавить коробку шурупов с телефона в гараже.
