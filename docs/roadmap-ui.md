# Роадмап разработки UI

Сведённый актуальный план интерфейса — поверх [`roadmap-inventory.md`](roadmap-inventory.md) (фазы 3–10) с учётом всех поправок: ревизии UI (D-44…D-50 в [`ui-architecture.md`](ui-architecture.md)), контейнеров (D-51/D-52), пересмотра D-33 (категории уже проставлены) и **desktop-парадигмы (D-53/D-54): главный вход — пространственный грид иконок-узлов**, таблицы/карточки/дерево — рабочие экраны внутри.

## Где мы сейчас (фаза 2 v1 — сделано, 2026-08-02)

✅ Работает на https://v1.spiridus.ru:
- `/w/[slug]` — универсальный рендерер workspace-узлов: сайдбар и home читаются из графа (D-50);
- v1-рендереры: `smart_list` (generic-таблица), `tree` (иерархия локаций);
- `/things` — generic-фолбэк (ступень 5 лестницы D-44);
- 44 категории с иерархией и статусы с `_i18n`+цветом уже в данных.

❌ Ещё нет: карточек узлов, виджетов, форм, фильтров, действий, прав, i18n-переключателя.

## Сквозные правила движка (действуют с этапа A, из D-45/D-49)

1. Пустой виджет не рендерится (кроме `always`); `ui.header` ≤ 5 виджетов.
2. Контракт виджета = план запроса: раскладка собирается в **один** SELECT (анти-N+1).
3. Виджет без реализации в реестре → generic-фолбэк с бейджем, не падение.
4. Контекст экрана = дефолты формы создания.
5. Клик-бюджеты — часть DoD этапов (см. таблицы ниже), не пожелание.

## Этап A2 — Desktop: рабочий стол, папки, симлинки (≈ 2–3 дня, D-53/D-54) — ✅ выполнен (2026-08-06)

> **v1:** `/` — корневой desktop из графа; **единая концепция «каждый узел — экран»** (`NodeScreen`): шапка узла → содержимое гридом иконок (references-размещения + под-локации + contains) → остальные свойства; папки, симлинк-демо (холодильник на столе и в Кухне), иконки по kind/category/полю `icon`; query-view рендерят свой контент. Маршрут `/w/…` стал легаси.
> **v2 (остаток):** drag-n-drop переупорядочивание; удержание над иконкой ~0.7с → создание папки (iOS-жест) либо перенос в существующую папку; ПКМ-меню «Разместить ещё в…» (симлинк из UI) и «Убрать отсюда» (удаляет размещение, не узел); переименование папок; breadcrumb-трейл фактического пути (sessionStorage). Первые мутации графа из UI — server actions (root до этапа F).

**Цель:** `/` — грид иконок на всё пространство браузера; навигация — как iOS-springboard.

| Артефакт | Детали |
|---|---|
| Рендерер `desktop` в `ViewRenderer` | responsive-грид; иконка из `ui.graph` kind-концепта + пер-узловое поле `icon`; подпись = name/`_i18n` |
| Размещения | `references`-рёбра с `order`; drag-n-drop переупорядочивания (соседи расступаются) |
| Папки | перетащил иконку на иконку → `view(subtype='desktop')`; открытие — вход внутрь, breadcrumb назад; вложенность любая |
| «Симлинки» | «Разместить ещё в…» в контекстном меню любого узла/строки → второе `references`-ребро; удаление размещения не трогает узел |
| Корневой стол в seed | `view_desktop_home` (slug `home`): ws_sklad как папка, пример вещи-иконки, «Одолжено» |
| `/` → рендер корневого desktop | список workspace'ов уходит внутрь стола |

**DoD:** главная — иконки; папка создаётся перетаскиванием; холодильник размещён и на столе, и в дереве хранения одновременно (один узел); разместить узел в закладки ≤ 2 действий; на телефоне грид перестраивается сам.

## Этап E — i18n-переключатель (≈ 1 день)

Все метки (kind, категории, статусы, виджеты) — из `_i18n` концептов; они **уже в данных** с фазы 1. Ru/en-переключатель в шапке; контент (`name`) остаётся на языке оригинала. **DoD:** «Холодильники» ↔ «Refrigerators», имя вещи не переводится.

## Этап F — Права и вход через Keycloak (≈ 2–3 дня, фаза 8 роадмапа, D-11)

Своего логина **нет** — вход через Keycloak (OIDC): Auth.js с Keycloak-провайдером в web; `DEFINE ACCESS TYPE JWT` (JWKS realm'а) + `AUTHENTICATE`-маппинг claim → узел `person` (JIT-провижининг при первом входе); обобщённый `PERMISSIONS WHERE` по [`access-control.md`](access-control.md) — без изменений; `<AccessGrantsWidget>` + модалка «поделиться»; root-доступ web выключается. **DoD:** редирект на Keycloak → сессия; сын видит только игрушки; папа поделился полкой — мама сразу её видит.

## Этап G — Actions v1 + lent-workflow (≈ 1–2 дня, фаза 9)

Контракт D-48: `mutate` (`mark_done`) и `relate` (`lend` → диалог `party`-пикера, `return`). View «Одолжено» уже существует. **DoD:** одолжить ≤ 3 действий; вернуть = 1. (`job`-действия — с воркерами, вне UI-роадмапа.)

## Этап H — PWA + мобильный (≈ 2–3 дня, фаза 10)

Automatic responsive (D-18), манифест + SW (офлайн-просмотр), камера для фото, опц. сканер штрих-кода → Wikidata-автозаполнение. **DoD:** добавить коробку шурупов с телефона в гараже.
